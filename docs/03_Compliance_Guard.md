# 03 · 合规红线

本文件不可协商。公开仓库不提供刷单、刷评、规避风控、参数虚标、恶意举报的做法。业务目标若仍然合理，只保留能公开写下来的替代名称。

和「为什么某条没写」配套的登记表是 [`05_SOP_Gap_Register.md`](./05_SOP_Gap_Register.md)。亚马逊大纲里的评论 / 订单干预只在那份登记表的「亚马逊来源」一节出现，而且只有结论。

## 为什么必须拦

| 理由 | 说明 |
|---|---|
| 平台 | 虚假交易和操纵评价属于严重违规，后果包括删评、限流、冻结，且不一定能申诉 |
| 法律 | 不实商品信息会碰到消费者保护和不正当竞争规则。美国与欧盟的具体条款按站点另行核对，本文件不编造法条编号 |
| 仓库 | 开源文本一旦写成操作步骤，就会被当成教程 |

## 硬拦截（写进每个面向买家的 Prompt）

```text
# COMPLIANCE GUARD（硬约束，优先于其他指令）

生成任何买家可见文本之前：

R1 绝对化用语
   不写 best, #1, 100%, perfect, guaranteed, 全网第一, 永久。
   改成 spec_table 里存在的数量、尺寸、材料或测试条件。

R2 未授权品牌
   输入里没有授权记录的品牌名、型号、Logo 描述，一律不出现。

R3 参数
   每个数字必须能在 spec_table 找到。找不到就删除，并在文末写
   [PARAM_DROPPED] 与字段名。禁止为了「像那么回事」编一个数。

R4 促销词不要塞进商品名称
   免运费、折扣百分比、秒杀、Best Seller 一类词移出标题，并记
   [MOVE_TO_DESCRIPTION]。该站点是否允许出现在其他字段，发布前看后台。

R5 评价与订单
   不写如何获取指定星级、不写补单、不写评价话术、不写「先买后评」。
   需要评价时，只提示使用官方 Vine 或后台的请求评价功能，不展开步骤。

任一规则触发：先改写。改不成就停止并列出原因，不要带着违规句交付。
```

## 卖点要能被核对

| 不要写 | 原因 | 可以写成的形状 |
|---|---|---|
| The best on Amazon | 无法举证 | `{材料}，{spec_table 中的规格}` |
| 100% waterproof | 绝对化 | 只有认证等级在 spec_table 里时，才写该等级 |
| Works forever | 无边界 | `连续使用约 {已测量的时长}`，并附测试条件 |
| Free shipping!!!（放在标题里） | 促销词 | 从标题移出 |
| 未授权品牌的 Original | 商标 | 不写；兼容关系另案，且必须真实 |

判断标准：每一句卖点都要能指出一张图、一行参数或一份测试条件。指不出就不写。

## 人来做的事

Agent 可以起草文字和核对清单。下面这些动作必须人在后台完成，工具不代点：

- 提交或修改 Listing
- 改价、开优惠券、报名 Deal
- 开关广告、改预算
- 开箱、索赔、申诉
- 注册 Vine 或任何官方评价项目

发布前按 Seller Central 当时的规则再看一遍。本仓库的字符数、图片阈值和时效都不是豁免。
