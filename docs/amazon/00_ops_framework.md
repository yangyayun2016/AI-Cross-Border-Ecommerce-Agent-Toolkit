# 运营总框架 · Amazon 美国站 / 欧洲站点

> 阶段按业务顺序整理为五段：**发货前 → 上架前 → 发货后 → 上架后 → 推广前期**。
>
> 大纲原文用「环节 1 / 2 / 3」混排阶段标签，有的任务写在环节 3，标签却是「上架前」。下文先给整理后的阶段，再单列矛盾，不把互相打架的标签同时当成执行顺序。
>
> 评价干预、订单干预类条目**不出现在执行清单里**。它们只在 [`docs/05_SOP_Gap_Register.md`](../05_SOP_Gap_Register.md) 登记到结论层。

人闸：选品、定价、备货数量、上架、广告开关、索赔与申诉，都由人确认。Agent 不代操作卖家后台。

## 1. 整理后的五段

### 发货前

货还没离开工厂或仓库之前要做完的决策与建档。

| 检查项 | 大纲里的阶段标签 | 本框架的处理 |
|---|---|---|
| 竞对信息收集 | 发货前 | 只记录公开可见的问题：是否有优惠券 / Deal、广告节奏、以及指标**名称**（ROI、CPC、CPA、ACOS、TACOS）。不收集、不复制评论干预手法。《新品推广计划表》《竞品推广节奏》的表样未附，栏位待后续 PR |
| 多变体与其他站点 | 发货前 | 保留两个决策问题：这个产品能不能做变体；北美是否同时布局加拿大。大纲里的「多国同步评论」不写入操作 |
| 项目跟进表 | 发货前 | 建档。字段形状见 [`Templates/amazon/launch_tracking.md`](../../Templates/amazon/launch_tracking.md) |
| 市场调研 | 原文无阶段标签 | 放在发货前。亚马逊数据源的字段词典待后续 PR，见 [03_official_tools.md](./03_official_tools.md) |
| 新品推广计划 / 广告 | 原文无阶段标签 | 只保留「发货前要有一份计划」这个检查项。SP/SB/SD 架构、日志、eCPM 待后续 PR |
| 透明计划 | 发货前 | 只保留大纲已写的判断：按商标 TM / R 标状态，在备货前决定要不要做。大纲其余只有标题「ASIN 注册 + 代码请求及下载 + OPR 开启」，**步骤待补**，本文件不编造 |
| 盈利模型、欧洲五国 VC 测算表指针 | 原文无阶段标签 | 发货前确认「有没有测算表」。美欧 SC/VC/DI/DF 公式与官方费率待后续 PR，本批不写数字 |
| 备货规划 | 发货前 | 记录 ASIN、出货数量、出货时间、预计到货时间（FBA）、开售时间。数量由人按项目目标决定，本文件不给安全库存公式 |
| 包材需求及提交时间 | 发货前 | 开发提需求，设计主导，运营核对。包装可含说明书与售后说明；邀评只走平台允许的官方请求评价途径 |
| 种子链接与样品规划 | 环节 1，原文未标阶段 | 放在发货前的样品规划：是否要为视频单独留样，以及是否使用**官方 Vine**。大纲里同时出现的铺评数量、评论节奏、测评，不抄进执行清单 |

文件名只保留形状，不填真人名：

- `{产品占位}-项目跟进表--{角色占位}-{日期}--新品`
- `{产品占位}-备货申请--{角色占位}-{日期}--老品`

大纲给出的运输时效是**实践值，待核实**，不是承运商承诺，也不是亚马逊官方时效：空运 15 天、卡航 30 天、铁路 40 天、海运 45 天。

体积重与体积的公式在 [`Templates/amazon/product_master_data.md`](../../Templates/amazon/product_master_data.md)。「箱重/365」待核实。

## 2. 大纲矛盾（已整理，不并排执行）

1. **环节 3 里的「检查 ASIN 收录、节点、类目」标成上架前。** 收录检查依赖已生成的 ASIN，本框架改到上架后。
2. **环节 2 同时出现「发货后」和「上架前」。** 图片需求按原文留在发货后；自拍、网红、品牌故事、旗舰店按原文留在上架前。不再用「环节 2」当作一个阶段。
3. **「站外辅助」写的是推广中，周围任务写的是推广前期。** 本框架放在推广前期，并注明原文用词。
4. **主推款的释义写进了季节性和快进快出，又另有一个没有定义的「季节款」。** 定位矛盾放在 [01_product_positioning.md](./01_product_positioning.md)，本文件不另造一套定义。
5. **标题字数在大纲内部不一致**（约 200 字符，以及完成度清单里的小于 75）。与知识图标题口径一起，并排写在 [`docs/02_Platform_Output_Spec.md`](../02_Platform_Output_Spec.md)。检查清单的默认建议只有一句：发布前按后台实时规则复核。

## 3. 和七个 Agent 的对应

| 阶段里的工作 | 现在能用的入口 | 本批没有写的部分 |
|---|---|---|
| 市场调研 | `Agents/01` 只解读调用方自己的表，脚本负责计数 | ABA、商机探测器、选品指南针字段词典 |
| 定位与定价算术 | `Agents/02` 读定位词典；费率必须调用方显式传入 | SC/VC/DI/DF 模板与官方费率 |
| 属性与合规文案约束 | `Agents/03` 指向属性实践；字符数只实测、不替官方下结论 | 关键词包、五点 / Search Terms / A+ 文案包 |
| 主图校验 | `Agents/04` 只保留 Amazon 主图规则卡，发布前复核 | 设计需求表、沟通表 |
| 视频时长算术 | `Agents/05` 时长由调用方给定 | 官方视频规格 |
| 广告盈亏算术 | `Agents/06` 只算调用方给出的数，不改后台 | SP/SB/SD 架构、日志、eCPM、自然流量 |
| 评论计数 | `Agents/07` 分类交给模型、计数交给脚本；不代写、不删评 | Q&A 专项、星级换算 |
