# 00 · 架构：阶段、脚本、Agent

本仓库把运营判断拆成可检查的输入、脚本算得出的数、以及必须人确认的动作。当前操作平台是 Amazon 美国站与欧洲站点。阶段定义在 [`docs/amazon/00_ops_framework.md`](./amazon/00_ops_framework.md)。

## 什么交给脚本，什么交给人

| 判断 | 交给谁 |
|---|---|
| 集中度、价格分箱、字符数、时长、给定费率下的毛利 | 脚本。模型不心算 |
| 这段话是否绝对化、参数是否在 `spec_table` 里 | Prompt 里的合规守卫，输出前自检 |
| 做不做这个品、备多少货、开不开广告、改不改价 | 人。字段 `decision_approved` 未显式为真时，下游只出草稿 |

缺字段就输出 `[INPUT_MISSING]` 并停下。没有的费率写成待核实，不用别的站点的百分比顶上。

## 阶段与模块

| 阶段 | 模块 | 本批状态 |
|---|---|---|
| 发货前 · 调研 | 01 | 可用：调用方提供的表 → 标准化 JSON → 指标。不可用：商机探测器 / 选品指南针 / ABA 字段词典 |
| 发货前 · 定位与价格算术 | 02 | 可用：定位词典 + 调用方传入的费率。不可用：官方佣金预设、VC/DI/DF 模板 |
| 上架前 · 属性与文案约束 | 03 | 可用：属性实践分栏、字符实测、合规守卫。不可用：关键词包与完整 Listing 文案 SOP |
| 发货后 · 图 | 04 | 可用：Amazon 主图规则卡与像素检查。不可用：设计需求表 |
| 上架前 · 视频 | 05 | 可用：按调用方目标秒数算时长。不可用：官方视频规格 |
| 推广前期 · 广告算术 | 06 | 可用：调用方费率下的盈亏线，动作为建议。不可用：广告架构、日志、eCPM |
| 上架后 · 评论计数 | 07 | 可用：已导出评论的归类计数。不可用：Q&A 专项；不代写评价 |

闭环仍然成立，但每一步缺资料时要停，而不是用旧站点的结构把空洞填上：

```text
01 解读已有表 → 02 定位（词典）+ 显式费率 → 03/04/05 草稿
→ 人上架 → 06/07 只诊断已导出的数 → 回流改文案或图 → 复测
```

一次只改症状指向的那一处。脚本没重跑，就不要声称复测通过。
